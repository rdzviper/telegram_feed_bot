# Telegram Feed Bot — Техническая спецификация

## Описание

Personalized feed-агрегатор для Telegram. Userbot (от лица пользователя) читает новые посты из подписанных им каналов, анализирует через DeepSeek, оценивает релевантность на основе матрицы пользовательских интересов, и форвардит релевантные посты в личный notify-чат.

## Проблемы которые решает

1. **Информационная перегрузка** — подписано на 50+ каналов, не успеть читать всё
   - Решение: автоматическая фильтрация по релевантности

2. **Дублирование контента** — одна новость в разных каналах/разных словами
   - Решение: детекция same_story, пропуск дубликатов

3. **Реклама и спам** — каналы постят коммерческие посты
   - Решение: автоматический детекция is_ad, пропуск

4. **Холодный старт** — как начать фильтровать если система не знает вкусы
   - Решение: адаптивный порог, всё форвардится пока нет интересов, затем автоматическое обучение через 👍/👎

## Входные требования

- TG_API_ID, TG_API_HASH — credentials Telegram приложения
- Session-файл (.session) — сохранённая авторизация userbot (от лица пользователя)
- BOT_TOKEN — токен вспомогательного Telegram-бота для отправки сообщений
- NOTIFY_CHAT_ID — чат куда форвардятся посты (обычно личный чат с ботом)
- ALLOWED_USER_ID — ID пользователя (для проверки авторизации команд)
- DEEPSEEK_API_KEY — API-ключ для анализа текстов

## Архитектура

### Компоненты

| Модуль | Назначение |
|--------|-----------|
| `bot.py` | Точка входа. Инициализирует Telethon userbot (от лица пользователя через session + API credentials), регистрирует обработчики входящих сообщений, синхронизирует диалоги для получения событий от всех подписанных каналов |
| `pipeline.py` | Основной pipeline: анализ поста → scoring → форвард → сохранение в БД |
| `analyzer.py` | Вызовы DeepSeek для извлечения концептов и детекции ad/duplicate |
| `handlers.py` | Обработчики Telegram-команд (`/stats`) и кнопок (👍/👎) |
| `database.py` | SQLite ORM. Таблицы: messages, channels, interests |
| `config.py` | Конфиг: API-ключи, пороги, пути |

### Поток данных

```
Telethon (userbot)
    ↓ получает posts от каналов
Pipeline (analyze)
    ↓ вызывает DeepSeek
DeepSeek API
    ← вернул: concepts, is_ad, same_story
Local Scoring
    ↓ суммирует веса концептов из матрицы
Adaptive Threshold
    ↓ сравнивает score с avg(last 200)
Decision
    ├─ is_ad/same_story → пропуск
    ├─ score ≤ threshold → пропуск (или drift)
    └─ score > threshold → форвард в notify_chat
Bot API
    ← отправляет медиа/текст + ссылка на канал + кнопки
Handlers
    ← пользователь нажал 👍/👎
Update Interests
    ← концепты ±1.0 (или -0.3 для дизлайка)
```

## Данные

### Таблица `messages`

```sql
id: int (PK)
channel_id: int
channel_name: str
orig_message_id: int (Telegram message ID)
bot_message_id: int (ID отправленного сообщения в notify_chat)
text: str
date: str (ISO 8601)
score: int (локальный score округлён)
is_ad: bool
same_story: bool
forwarded: bool
is_drift: bool
concepts: JSON (list[str])
local_score: float
user_choice: str ("like" | "dislike" | NULL)
created_at: datetime
```

### Таблица `interests` (матрица весов)

```sql
topic: str (PK) — концепт (e.g. "Sony", "игра", "цены")
weight: float — вес (может быть отрицательным)
```

При лайке: `weight += 1.0`  
При дизлайке: `weight -= 0.3`

### Таблица `channels`

```sql
channel_id: int (PK)
channel_name: str
active: bool (если false — не анализируем посты из канала)
seen: int (всего сообщений обработано)
forwarded: int (всего отправлено в notify_chat)
likes: int (всего лайков из канала)
dislikes: int (всего дизлайков)
```

## Алгоритм

### 1. Холодный старт (интересов = 0)

- Пороговый threshold = avg(last 200 seen posts) = 0
- Все посты (score ≥ 0) форвардятся
- Пользователь начинает лайкать → концепты накапливаются в interests

### 2. Адаптивный порог

```python
threshold = avg(local_score for last 200 posts)
forward if local_score > threshold
```

Система автоматически подстраивается: чем популярнее интересы, тем выше порог.

### 3. Локальный scoring

```python
concepts = DeepSeek.extract(text)
weights = db.get_weights(concepts)  # {topic: float}
local_score = sum(weights[c] for c in concepts)
```

Если концепт не в матрице → вес 0 → не влияет на score.

### 4. Drift-механизм

Каждые N постов (конфиг `DRIFT_EVERY_N`, дефолт 20) один пост форвардится **вне зависимости** от score. Нужен чтобы:
- Обучить бота на новые темы
- Разбавить монотонность в случае очень узких интересов

Drift-пост помечается 🔍 эмодзи.

### 5. Фильтры

- **is_ad**: реклама, промо, партнёрский контент, призывы купить/подписаться → пропуск
- **same_story**: дубль-инфопов за последние 24 часа → пропуск (даже если score высокий)
- **is_channel_active**: канал отключен через `/stats` → пропуск
- **rate_limit**: не более N постов в час → пропуск (конфиг `RATE_LIMIT_PER_HOUR`, дефолт 20)

## Форвард

### Текстовый пост

```
[ссылка на канал] [название канала]

[текст поста, до 3500 символов]

[кнопки 👍 👎]
```

### Пост с медиа

```
[медиа: фото/видео/GIF/документ]

caption: [ссылка на канал] [название канала] + [текст, до 900 символов]

[кнопки 👍 👎]
```

Медиа загружается через `tg_client.download_media()` и переотправляется через Bot API вместе с caption.

### Кнопки

- 👍 `like:{msg_id}` — +1.0 к весам всех концептов поста
- 👎 `dislike:{msg_id}` — -0.3 к весам всех концептов поста

Оба варианта обновляют счётчики канала и сохраняют выбор пользователя.

## Команды

## Логирование

### INFO уровень

- `Incoming: channel=...` — сообщение получено
- `Analyzed: ... concepts=... local_score=...` — результат анализа
- `Forwarding: ...` — решение переслать

### DEBUG уровень

- Вызовы DeepSeek
- Причины фильтрации (is_ad, same_story, score < threshold)
- Обновления интересов

### DEBUG_ALL_MESSAGES=1

Логирует **каждое** входящее событие (в INFO):
```
[DEBUG] chat_id=... post=... is_channel=... text=...
```

Полезно для отладки холодного старта.

## Требования к DeepSeek

### Запрос `analyze(text, recent_headlines)`

Входные параметры:
- `text`: текст поста (до 1500 символов)
- `recent_headlines`: список заголовков последних постов за 24ч (для детекта same_story)

Ожидаемый ответ (JSON):
```json
{
  "concepts": ["Sony", "игра", "цены"],
  "is_ad": false,
  "same_story": false
}
```

**Правила нормализации концептов:**
- Именительный падеж
- Единственное число
- Одна каноническая форма: "сони" → "Sony", "игры" → "игра"
- 3–7 концептов
- Исключить стоп-слова ("новость", "рынок", "компания")

## Поведение холодного старта

**День 1–2:** Пользователь видит все посты. Нажимает 👍 на интересные.

**День 3+:** После ~5–10 лайков начинает формироваться матрица. Пороги становятся строже автоматически. Пользователь видит преимущественно релевантные посты, но drift каждые N постов всё ещё позволяет обнаружить новые темы.

## Граничные случаи

### 1. Новый концепт без история

Концепт с weight=0 не влияет на local_score. Пост где есть новый концепт + известные получит score только от известных.

### 2. Концепты с очень разными весами

Если "Sony" имеет weight=50, а "цены" — weight=1, их сумма даст правильный score, но посты про "Sony и цены" будут доминироваться одним концептом. Это корректное поведение — пользователь явно выбрал через лайки.

### 3. Очень узкие интересы (все концепты > threshold)

Drift механизм спасает: раз в N постов один пройдёт, даже если score низкий.

### 4. Адаптивный порог упирается в ноль

Если ВСЕ последние 200 постов имели score < 0 (много дизлайков), то threshold может быть отрицательным. Посты с score ≈ 0 начнут проходить. Это нормально — система восстанавливается.

## Расширения (future)

- Decay весов со временем (старые интересы медленно теряют влияние)
- Cluster концептов (синонимы "Сони", "Sony", "Sony Interactive" → одна группа)
- Командные интересы (группа может совместно обучать бота)
- Экспорт интересов / резервная копия матрицы
